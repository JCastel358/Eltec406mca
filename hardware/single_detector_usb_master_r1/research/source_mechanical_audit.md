### ESP32 module/header

- U1 is a 30-position ESP32 DEVKIT V1 pattern: two 1x15 rows, 2.54 mm pitch, 25.4 mm row separation. Pads are 2 mm circles with 1 mm drills in the source. The existing photograph supports a 30-pin USB-C module, but exact ESP32 module vendor, underside height, and USB plug keepout remain unverified.
- Row A: pad 1 (3V3) at (86.08,87); pad 15 (D23) at (50.52,87). Row B: pad 16 (VIN) at (86.08,112.4); pad 30 (EN) at (50.52,112.4). Each row runs toward decreasing X.
- **Source defect:** there are actually 31 pads because pad 28 occurs twice. One duplicate pad 28 is coincident with pad 27 at (58.14,112.4), while the intended pad 28 is (55.6,112.4). The duplicate is present both in the board and original library. Preserve the proper 30 pin locations, remove the coincident erroneous duplicate in the new design, and verify symbol-to-footprint parity.
- Original module footprint is marked `smd` despite through-hole pads and has no courtyard. Recreate as an appropriate socket/module assembly representation and include physical keepouts. Do not use the source metadata unchanged to generate placement data.
- Module ground pins 2 and 17 have differently named nets in the source; do not infer intentional isolation merely from these names because the plug-in module may connect them internally. Likewise the ADC module ground headers need explicit continuity reasoning.

## Library and assembly completeness of the original

- `Eltec Footprints.pretty` contains 9 supplied `.kicad_mod` files: ADS1256_BOARD, AMS1117, Battery, Emitter, ESP32_DEVKITV1, IRLB8748, LMC6062, Sensor, and Untitled.
- No standalone current `.kicad_sym` library or `sym-lib-table` is included. Custom symbols are embedded inside the schematic under `lib_symbols` (`Eltec Part:*`); these can be extracted into the new project-owned symbol library.
- `fp-lib-table` also names `${KIPRJMOD}/eltect footprintw.pretty`, but that directory is not present in the current project (only in an excluded older backup). New project libraries must not retain this stale dependency.
- Original `production/bom.csv` lists electronic SMD parts, but omits RV1, the headers/modules, jacks, wire pads, and logo. It is historical evidence, not a complete purchasing/assembly BOM for the new project.
- Original RV1 uses `Potentiometer_THT:Potentiometer_Bourns_3296W_Vertical`, 1 kOhm, 2.54 mm pin pitch. User requests only the ESP32, ADS1256 and jacks be unpopulated, so any retained trimmer and sockets need explicit assembly purchasing support rather than inheriting the old BOM omission.
- Original production exports identify KiCad 10.0.3 and a 2026-08-04 timestamp. They are stored for comparison only; never submit these as outputs for the replacement design.

## Decisions recoverable without asking the user

- Preserve the original 86 x 103 mm outline and jack/header locations as the first trial geometry; label the revised placement preliminary until actual module clearances and enclosure fit are checked.
- Preserve the original wire-pad polarity and avoid pretending the emitter and detector bodies are on the PCB.
- Rebuild the malformed module footprint metadata and ESP32 duplicate pad in new project libraries.
- Retain independent emitter and detector supply returns where the schematic genuinely isolates them; do not short returns solely to simplify routing.

## Evidence still needed before mechanical/fabrication release

1. Confirmation that the replacement must fit the photographed enclosure with exactly the original carrier outline and jack/USB locations; no dimensioned enclosure/block drawing was supplied. Existing native carrier geometry can be used for trial layout without claiming fit approval.
2. Actual socket part numbers or allowed substitution, installed header height, underside component protrusion, and USB connector/cable clearance. Original pin-center geometry is known; vertical clearances are not.
3. Actual replacement barrel-jack part or confirmation that the existing two jacks will be transferred and fit the original slot pattern. Assigned footprint identity alone is not actual part authentication.
4. If moving from soldered wires to populated detachable connectors, connector selection and any enclosure clearance constraint must be resolved; original source does not select such connectors.
5. Actual optical-block CAD/lead drawings if the design scope expands to mounting detector/emitter bodies directly. The current supplied design only carries wire attachment points.
